# 狐隱 KOGAKURE｜2026-11-17 安全盤查與修改必要性

本文件保留 **2026-11-17 初次靜態盤查**的結論（原始碼基準 `65b8559`）；不表示後續每個 Git 提交或正式 Supabase 環境已重新稽核。當時未操作正式帳號、SQL、Storage 或部署，也未進行滲透測試。

## 當次查核結果

- 當次 `npm audit`（含正式環境依賴檢查）回報 **0 個已知依賴漏洞**。漏洞資料庫會更新，此結果不是永久保證。
- GitHub Actions 以公開 Publishable Key 建置，且具備拒絕 Secret/Service-role Key 的檢查；部署工作權限限制於必要範圍。
- PR 驗證流程包含高風險依賴稽核與離線回歸測試；Dependabot 一般大版本升級噪音已降低，但安全更新仍需人工審核。
- 員工帳號敏感操作由帶 JWT、身分及委派權限檢查的 Edge Function 控制；高權限金鑰未設計為前端可讀。
- 資料庫程式包含 RLS、受控 RPC 及私有 schema，分隔公開寫入與旅人訂單／預約／帳務資料。**正式環境套用狀態未由靜態檢查證明。**

## 風險及優先順序

| 優先 | 問題 | 為何需要改善 |
| --- | --- | --- |
| P1 | 匿名點單及預約可繞過姓名／伺服器冷卻 | 無可信來源限流可能遭大量提交及資源耗用 |
| P1 | 訪客姓名舊長度限制已移除 | 非空白檢查不等於請求大小安全，需要合理位元組上限 |
| P1 | RLS 與 Edge Function 正式版本未核實 | 程式碼有權限規則不代表正式服務部署一致 |
| P2 | 訂單、預約、帳號永久刪除 | 需要歷史保留、可復原備份與權責界線 |
| P2 | 名帖多人編輯及 Storage 舊照片 | 可能產生資料覆蓋與無主素材 |
| P2 | 外部或上傳音樂 | 使用授權、第三方連線及必要署名尚未盤點 |
| P2 | 公開文件與網站素材暴露過多內部資訊 | 文件只保留必要變更和設計理由；不得存放高權限憑證、個資與營運明細 |

## 已知安全邊界

- 公開網站可包含 Publishable Key，但不得包含 `sb_secret_*`、service-role、JWT 簽章秘密、資料庫密碼或員工密碼。
- 匿名存取不得讀取私人訂單、預約、帳務及員工帳號；停用或未授權員工不應獲得敏感模組的資料存取。
- `accounts.manage` 的受限委派不得允許使用者自我提升權限。
- 永久刪除、帳務與資料庫結構變更涉及備份、不可回復風險和正式環境授權。
- 離線 QA 與 GitHub Actions 通過不等同實際資料庫隔離、行動裝置或營運狀態的完整驗收。

此文件為風險紀錄，非部署操作程序。最新狀態以 `docs/ROADMAP.md` 及後續獨立查核為準。
