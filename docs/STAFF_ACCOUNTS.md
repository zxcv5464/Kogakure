# 狐隱 KOGAKURE｜員工帳號與權限變更必要性

## 已完成變更

- 員工採獨立的登入帳號名稱與密碼；原有正式管理員 Email 登入保持相容。內部 Auth 識別不等於可寄送信件地址，**不會寄出任何員工邀請**、確認或重設密碼郵件。
- 自訂登入名稱具有唯一性與格式驗證；員工密碼使用 8～16 字、至少一個英文字母和數字的規則。Supabase Auth 保存密碼雜湊，不在管理資料表留下可查看的原始密碼。
- 員工自助密碼介面納入「管理總覽」→「我的帳號安全」區域，設計上須先驗證目前密碼，且只能修改**自己的**密碼，不增加其他帳號的管理權限。「忘記目前密碼」情況仍維持受權限保護的管理員協助重設，而非繞過身分確認。
- 原有舊版員工識別與權限保留相容路徑，避免帳號形式調整造成身分及營運資料遺失。
- `accounts.manage` 可受限委派，但不得修改自己、其他帳號管理者，或授予超出自身範圍的權限。
- 員工帳號停用與永久刪除分離：停用保留歷史及身分；永久刪除移除 Auth 身分與授權，名帖、茶宴、預約和帳務資料不因此被整批刪除。

## 目前權限邊界

| 權限 | 範圍 | 區分的必要性 |
| --- | --- | --- |
| `staff.manage` | 人員名帖、照片、排序 | 不等於員工登入帳號管理 |
| `menu.manage` | 菜單與價格 | 不等於旅人訂單管理 |
| `orders.manage` | 訂單與旅人資料 | 降低非接單員工的資料接觸面 |
| `keepsakes.manage` | 狐影留帖交付及紀錄 | 私人照片交付與其他模組隔離 |
| `feedback.manage` | 狐語迴音審核及回覆 | 公開留言需內容審核 |
| `booking.manage` | 指名、方案與預約 | 不授予整張名帖任意寫入 |
| `accounting.manage` | Gil 帳務、統計、CSV | 敏感薪資與收支需獨立授權 |
| `accounts.manage` | 受限管理其他員工帳號 | 防止自我擴權及修改其他權限管理者 |
| `announcements.manage` | 公告 | 發布權責獨立 |
| `bgm.manage` | 背景音樂來源及音檔 | 隔離 Storage 寫入 |
| `services.manage` | 服務介紹、圖片及公開狀態 | 隔離服務內容編輯 |
| `shifts.manage` | 營業設定及他人出勤 | 與自行出勤分開 |
| `shifts.attend` | 本人出勤與常用名稱 | 不可藉此更改營業日或他人資料 |

每個權限都是可操作權限，並非唯讀授權。正式資料庫仍需以 RLS、RPC 與 Edge Function 再次檢查，不可依賴前端選單可見性。

## 對應資料變更

- `20261115_01_employee_accounts_permissions.sql`：員工權限基礎。
- `20261115_04_employee_usernames.sql`：唯一登入名稱及舊帳號相容。
- `20261115_17_delegated_accounting_permission.sql`：帳務委派和資料保護。
- `20261115_28_complete_admin_module_permissions.sql` 與 `20261116_03_bgm_management.sql`：補齊模組委派權限。
- `supabase/functions/manage-employee-accounts/index.ts`：服務端身分、帳號狀態和委派邊界驗證。

## 尚存風險

- 帳號刪除無法還原原密碼與 Auth 身分；帳務作者參照可能變為空值，但歷史金額應保留。
- 密碼變更後的既有瀏覽器 session 不一定立即失效；實際存取仍須以當前授權狀態為準。
- 是否已在正式 Edge Function／資料庫套用所有權限版本，需要獨立核對；不得因前台顯示已完成就視為已驗收。
