# 狐隱｜員工名帖管理操作優化與 BUG 盤查（2026-11-10）

## 本輪範圍與限制

本輪僅修改前端員工管理模組、Supabase 客戶端 CRUD 回傳驗證與圖片上傳行為。沒有執行資料表 migration，也沒有使用正式管理員帳號對店長資料庫新增、修改、刪除或上傳測試資料。

正式環境需由具權限管理員完成最後一次人工驗收，再推送公開網站。

## 已修正／改善

1. **服務分類不能連續輸入**：舊版每打一個分隔符號就立刻拆解成陣列，會吞掉尾端逗號或頓號。現在在編輯過程保留原始輸入，儲存時才將逗號、頓號、換行轉為不重複的標籤。
2. **未儲存資料容易遺失**：切換員工、按新增、關閉編輯、更新清單、後台功能選單、後台 Logo 返回前台、登出時會詢問是否放棄；視窗關閉／重新整理使用瀏覽器原生提示；處理中禁止上述操作。按相同頁面選單不重複提醒。
3. **選照片後立即上傳造成浪費**：先用本機 Object URL 預覽，只在「儲存」時轉換並上傳兩種 WebP；取消時不會上傳。上傳第二張失敗時，嘗試移除已上傳的第一張。
4. **儲存結果與畫面狀態不同步**：成功後更新編輯基準、儲存提示與本機清單；即使刷新清單失敗，也不會把已儲存成功誤報成失敗。
5. **沒有影響筆數也誤報成功**：INSERT、UPDATE、DELETE 均檢查實際返回的資料。編輯既有員工使用 UPDATE，避免其他管理員已刪除該員工時由 UPSERT 意外重建。
6. **Supabase 錯誤難以判斷**：可顯示一般 Error 及 Supabase 回傳物件的 message；色碼會在寫入前檢核。
7. **清單與表單難操作**：新增姓名／職稱／服務搜尋、草稿／公開篩選、總數統計、選中狀態、明確分段、儲存狀態、欄位說明及公開提示；圖片可預覽／重選；名帖可從新分頁查看前台。
8. **小螢幕操作**：手機上選擇員工會捲到編輯區；手機版儲存列不再浮在文字欄位上，新增社群輸入不產生橫向捲動；圖片選擇控制可用鍵盤聚焦。

8. **人員排序難以操作（2026-11-10 追加）**：移除表單內的顯示順序數字欄，於員工清單新增「排序」模式，桌面拖曳或使用上下箭頭（手機亦可）；常態只更新一筆 `sort_order`，遇相鄰或重複的舊排序數字才重新拉開間距。重排時禁止覆蓋未儲存的表單內容，失敗後嘗試還原並刷新清單。
9. **前台名冊資訊架構（2026-11-10 追加）**：使用「狐姬名冊」作為前台標題與導覽名稱；人員少於 6 位不顯示搜尋；達 6 位才提供預設收合的「尋找狐姬」，展開後可搜尋及按服務篩選，不用常駐整排分類按鈕。

## 自動化驗證

- `npm run build` 與 GitHub Pages `VITE_BASE_PATH=/Kogakure/` 正式版編譯。
- `node scripts/qa-staff-editor.mjs`：使用隔離瀏覽器模擬 Supabase 管理員、讀取、建立、更新、寫入失敗、零筆寫入、刪除、圖片暫存及上傳、拖曳／方向箭頭排序；資料完全攔截，不寫入店長 Supabase。
- `node scripts/qa-staff-order.mjs`：測試一般順序移動、重複排序值、相鄰數字及整數上下界。
- `node scripts/qa-staff-directory.mjs`：以 2 位／7 位模擬狐姬測試搜尋顯示門檻、收合面板、分類、清除及手機排版。
- 桌面 1440 px、平板 768 px、手機 390 px／320 px 的橫向溢出、搜尋、社群欄位、儲存操作測試。
- `node scripts/qa-static-pages.mjs`：檢查 GitHub Pages 清爽網址與管理模組入口。

## 還需要進一步處理（非本輪已修復）

- **瀏覽器的上一頁／下一頁（SPA history）**：離開警告涵蓋介面內的連結及重新整理，但尚未加入跨瀏覽器都穩定的 history 路由阻擋。正式使用時不要依賴上一頁來保留未儲存草稿。
- **極端排序值／多人同時排序**：一般移動只更新一筆排序值；若既有數字重複或緊鄰，需要依序更新多筆。部分寫入失敗時會嘗試還原並重新載入，但多筆更新不是資料庫單一交易。若未來需頻繁共同排序，可改用具 RLS 權限檢查的資料庫交易函式。
- **多位管理員同時編輯同一名帖**：目前最後成功儲存者可能覆蓋較早的修改。正式多人同時編輯前應加入資料版本比對或樂觀鎖。
- **圖片存放量**：取消「尚未儲存」的新照片不會上傳，上傳部分失敗會嘗試清理；但已儲存並被替換的舊照片與已刪除名帖照片仍留在 Storage，避免誤刪共享資源。需後續做受權限保護、可預覽清單的孤兒檔案清理作業。
- **正式 Supabase 驗收**：需管理員實測登入、RLS、修改現有草稿、上傳照片、變更公開狀態、前台顯示；尤其應確認真實網路環境的上傳失敗提示與圖片大小。

## 管理員手動驗收順序

1. 在 `/admin/staff` 搜尋員工，切換「全部／已公開／草稿」，確保數量正確。
2. 打開某員工，修改服務分類但不儲存，嘗試切換員工與回管理總覽，確認警告能取消離開。
3. 修改姓名與長篇介紹並儲存；再點清單的「排序」，拖曳或用上下箭頭移動，刷新後檢查排序與資料都一致。
4. 選取新圖片，先取消編輯再重選，確認取消時沒有新增 Storage 物件；實際儲存時確認產生大圖與縮圖。
5. 新增測試名帖為草稿，確認前台不顯示；再改為公開並查看前台。最後依管理規範清理測試名帖。
6. 用手機查看含社群連結的名帖編輯器，確認所有欄位與底部按鈕可以操作。

> 注意：後台畫面是否隱藏按鈕不構成權限限制，正式資料存取仍由 Supabase Auth + PostgreSQL RLS 控制。
