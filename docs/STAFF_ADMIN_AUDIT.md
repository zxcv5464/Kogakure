# 狐隱 KOGAKURE｜員工名帖管理 BUG 修正與必要性

原始盤查日期：**2026-11-10**。此文件記錄修正結果和剩餘風險，不包含後台操作指引。當次修改沒有操作店長正式 Supabase 資料庫或新增測試名帖。

## 已修復與改善

| 問題 | 變更 | 必要性 |
| --- | --- | --- |
| 服務分類輸入被截斷 | 編輯期間保留原字串，儲存時才拆分並去重 | 避免逗號、頓號或換行輸入遺失 |
| 未儲存內容遭切頁覆蓋 | 加入離開提醒與處理中保護 | 降低草稿遺失與誤操作 |
| 選圖立即上傳 | 改成本機預覽、確認儲存才上傳 WebP | 減少不必要的 Storage 檔案 |
| 寫入成功提示不正確 | 檢查實際受影響資料並同步本機狀態 | 避免零筆修改被誤判成功 |
| UPSERT 意外重建舊員工 | 既有名帖使用明確 UPDATE | 避免他人已刪除資料又被重建 |
| 錯誤資訊不足 | 改善 Supabase 錯誤顯示與色碼檢查 | 降低無法判斷失敗原因的情況 |
| 長表單及手機難操作 | 清單搜尋、公開／草稿篩選、分段、圖片預覽與手機排版 | 減少管理成本 |
| 數字排序不直覺 | 改為桌面拖曳及手機可用的上下移動 | 不再要求人工輸入排序數字 |
| 公開名冊搜尋繁雜 | 名稱調整為「狐姬名冊」，達 6 位人員才提供收合式搜尋／服務篩選 | 保持名冊畫面簡潔 |

## 驗證範圍

- 已有員工編輯、排序及公開名冊相關的隔離自動化回歸測試，涵蓋一般成功、寫入失敗、排序邊界及手機排版。
- 自動化測試使用隔離資料，不等於已驗證正式資料庫的 RLS、Storage 寫入與權限分工。
- 後台隱藏操作按鈕不代表資料獲得保護，正式權限仍應由 Supabase Auth／RLS／RPC 驗證。

## 仍需改善

- 瀏覽器上一頁／下一頁的未儲存內容保護仍需跨瀏覽器確認。
- 極端排序值或多人同時排序可能涉及多筆非原子寫入；資料庫單一交易方案尚未完成。
- 多位管理員編輯同一名帖仍有最後儲存者覆蓋先前內容的風險，需要資料版本比對。
- 舊名帖圖片被替換／刪除後，Storage 可能留有孤兒圖片；清理機制須先確認引用與授權。
- 正式環境的人員建立、權限、圖片上傳及失敗提示尚需人工驗收。
