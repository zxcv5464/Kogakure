# 狐隱 KOGAKURE｜四週值班排班變更與必要性

## 已完成變更

- 前台與後台均以**台灣時區當週週一至週日，加未來三週**為顯示範圍，共 28 天；每週自動滾動，不另行改寫歷史出勤資料。
- 沒有營業設定或 `is_open=false` 的日期預設休館，避免向訪客顯示虛構的開店日與館員。
- 前台以七欄月曆呈現營業狀態、活動及出勤摘要，完整資訊由當日詳情承載，改善小螢幕擁擠問題。
- 後台月曆採總覽與單日編輯分離，減少四週長表單造成的閱讀負擔；保留鍵盤焦點及低動態偏好。
- 營業日可帶有選填活動名稱、時段及備註。只有營業日才會對訪客顯示出勤名單。
- 員工出勤顯示名稱與登入帳號名稱分離，可保存常用 RP 名稱，避免公開登入識別；修改常用名稱不會自動改寫歷史班次。
- 管理員本人出勤與員工自行出勤分表或受限保存，維持可追蹤的身分與權限區別。

## 必要的權限界線

- `shifts.manage`：營業日、活動設定及他人班次管理。
- `shifts.attend`：啟用員工僅能管理自己在已公告營業日的出勤，不得改動其他員工或營業設定。
- 匿名者只能讀取允許公開的營業與出勤資訊，不能新增、更新或刪除班次。
- 公開的出勤顯示名稱不包含密碼、Email、帳號名稱與管理權限；出勤登記不代表已通過額外的館方審核，也不保證一定能接受預約。

## 值班頭像（2026-11-23 新增）

- 前台選取營業日後，當天出勤人員的**姓名左邊**顯示小型圓形頭像；沒有照片或圖片失效時顯示簡約預設圖示，姓名仍正常顯示。
- 後台「值班排班管理」有獨立**值班頭像管理**區塊，能針對管理員本人、啟用的員工上傳／更換／移除照片。員工可維護自己照片；受委派排班管理者可維護啟用員工的照片，不可任意修改其他管理員的照片。
- 每位帳號共用一張值班照片，跨日期沿用；不依公開 RP 名稱比對，因此更名不會造成照片錯置。這項功能不更動既有出勤紀錄。
- 瀏覽器會將原圖裁成 360×360 WebP，支援 PNG/JPEG/WebP/AVIF，來源需小於 12 MB；照片存入獨立公開 `shift-avatars` bucket，而非員工帳號資料欄位。
- `supabase/migrations/20261123_01_shift_profile_images.sql` 建立獨立的頭像表、公開讀取規則、登入者受限寫入權限與 Storage 政策。**部署前必須在正式 Supabase 套用 migration；GitHub Pages 不會自動套用資料庫。**
- 新表未上線前，前台可保持只顯示姓名，避免因未部署的照片功能導致整張排班月曆無法讀取。
- 發布後要驗證：公開營業日的照片顯示、休館日不顯示出勤、員工只能修改自己照片、排班管理者只能修改授權員工、圖片更換與移除、手機頭像尺寸，以及與原出勤流程的相容性。
