# 狐隱 KOGAKURE｜四週滾動值班排班

## 系統行為
- 前台 `/shifts/` 顯示台灣時區的「當週（週一至週日）＋未來三週」，共四週、28 天，使用七欄月曆與可點選的日期詳情。
- 每週一（台灣 00:00）日期自動推移一週：上一週移出顯示範圍，最末端補入新一週。頁面維持開啟時，每分鐘檢查日期，切換視窗或重新開啟也會更新。不會建立背景排程、不會刪除歷史資料。
- 日子分成「未公告」（無資料列）、「營業」（is_open=true）及「休館」（is_open=false），**未公告絕不預設營業**。
- 營業日期顯示館方設定的時段、備註與出勤館員的顯示名稱。已經休館／未公告的日子不公開出勤姓名。
- 沒有任何營業日紀錄時，前台全部顯示「未公告」，不會生成虛構營業日或值班人員。

## 前台旅人四週月曆（七欄）
- 前台「狐火值夜曆」改為**星期一至星期日七欄 × 四週**月曆，畫面頂部清楚顯示四週日期範圍、已公告營業日數及活動數。營業、休館、未公告及今天各有容易辨認的視覺標示。未公告絕不當作營業。
- 每個日期是一個可點選、可用鍵盤操作的按鈕；月曆只摘要顯示營業狀態、時段、活動（如有）與出勤人數，**不把所有狐姬姓名擠進日期小方格**。
- 點日期後，下方「當日資訊」顯示日期與星期、實際營業時段、活動名稱、館方備註及完整出勤名單；若當日休館或未公告，則明確告知不對外接待或尚待公告，不顯示出勤名單。營業日提供前往「預約」頁面的既有網站連結，不代表即時保證可預約。
- 手機上保留不需左右捲動的七欄日期；日期方格僅顯示日期、營業狀態與有活動時的標記。詳細時間、活動與狐姬名單請點日期查看。點選後會將焦點及視窗帶向當日資訊，並尊重減少動態效果偏好。
- 前台與後台使用同一組 `shift_open_days`、`shift_attendance`、`shift_owner_attendance`，不增加或修改任何出勤資料；資料仍依台灣時間四週滾動。

## 後台四週月曆與每日彈出編輯
- 後台改為橫向**星期一～星期日七欄、連續四列**，維持本週＋未來三週共 28 個日期。桌面直接顯示完整月曆，手機可在月曆區左右滑動；每格清楚標示日期、營業／休館／未公告、營業時間與出勤人數。**月曆方格不顯示出勤人員姓名**；有安排活動且當日營業時，才額外顯示活動名稱。詳細人員名單仍保留在當日彈出編輯視窗中。
- **點日期**才開啟當日「值班安排」彈出編輯視窗；主月曆僅負責總覽，不放置每一日的長表單。可點右上角 X、下方完成／關閉、背景或 Esc 關閉視窗。
- 管理員在彈出視窗中設定營業日與時段／備註、**活動安排（選填，120 字內）**，以及新增其他館員出勤、取消當日出勤或替自己報班。活動名稱獨立儲存於 `shift_open_days.event_title`；清空欄位儲存即可移除活動，改設休館時也會清除活動標題。員工可檢視已公告日期及登記／取消／修改自己的出勤名稱。後端權限與資料表維持原規則。
- 當日操作成功後，彈窗中會顯示成功／失敗提示，同時主月曆會更新該日摘要。送出操作時暫停關閉彈窗，避免誤認儲存失敗。鍵盤操作可用 Tab 移動與 Esc 關閉，關閉後焦點返回原日期。

## 管理員／員工後台
- `/admin/shifts/`：正式管理員可設定每一天營業、休館或未公告，並填寫選填的營業時段與備註。每一天按下「儲存開店設定」便會立刻同步資料庫。
- 管理員可透過「我的出勤顯示名稱」（預設婆婆，可自行修改）直接登記或取消自己的出勤，無須額外建立員工帳號。顯示名稱僅用於公開排班，不參與登入身分驗證。
- 管理員在排班下拉選單中優先看到員工儲存在資料庫的「常用出勤名稱」；未設定時才使用員工帳號顯示名稱。兩者不同時，下拉選項會附上帳號顯示名稱供辨識，公開排班只顯示出勤名稱。管理員可為員工新增班次或直接取消出勤，**不會再跳出取消確認視窗**。
- **任何有效且已登入的員工帳號**都能進入「值班排班」；不需要另行勾選員工的管理權限。員工可以自行填寫「我的出勤顯示名稱」（最多 100 字），在**已設定營業且日期為今天或未來**的日子登記或取消自己的出勤，無法設定營業日期或更動其他員工的班次。
- 員工可按「儲存常用出勤名稱」將自己的 FFXIV／RP 名稱儲存在 `employee_accounts.shift_display_name`，讓管理員在其他裝置排班也能讀到。員工自行報班、修改既有班次名稱時，也會同步更新這個偏好；如果沒有偏好才回退到員工帳號的 `display_name`。若某天早已排班，請在該日按「儲存我的出勤名稱」才會更改舊班次；不會自動覆寫歷史排班。資料庫用 `auth.uid()` 與 `active` 檢查身分，且只開放員工更新自己的 `shift_display_name` 欄位，不影響帳號密碼、身分、權限、名帖。
- 管理員開店日由管理員自主填寫，不預先決定每週幾天、星期幾或時段。新增的一週是空白的「未公告」。
- 備註或時間需要按下該日儲存才會生效；變更週別時請注意尚未儲存的欄位會消失。

## 資料庫、隱私與權限
- SQL `supabase/migrations/20261115_09_rolling_four_week_shifts.sql`：新增 `shift_open_days` 與 `shift_attendance`。另有 `20261115_10_owner_self_attendance.sql` 新增獨立的 `shift_owner_attendance`。`20261115_11_employee_shift_display_name.sql` 允許員工自訂與編輯既有出勤顯示名稱，授權僅限 `UPDATE(employee_name)`（管理員出勤則僅限 `UPDATE(display_name)`）。`20261115_12_employee_preferred_shift_name.sql` 為員工帳號增加僅限本人更新的 `shift_display_name`，並從最近的既有出勤紀錄回填一次常用名稱。`20261115_13_shift_event_title.sql` 為營業日增加可選擇的活動名稱欄位；沿用既有管理員限定的營業日寫入權限。保留原始班次與既有茶宴、預約、名帖資料。
- RLS：營業日期供所有訪客讀取，只允許正式管理員寫入；員工與管理員的出勤紀錄在營業日才對訪客公開。有效員工只能替自己在已公告營業日新增或刪除出勤。管理員可管理員工出勤，並以 `auth.uid()` 驗證正式管理員身分後，新增或刪除自己的 `shift_owner_attendance`。
- 每個員工每個日期只能有一筆出勤紀錄；參照 `employee_accounts(user_id)`，如果員工帳號被刪除，相關出勤也會跟著清除。
- 前台同時顯示管理員及館員的出勤顯示名稱，不顯示密碼、電子郵件、登入帳號、權限資料。
- 人員名稱在**報班當下**以當時已設定的 RP 名稱保存；優先讀取帳號內的常用出勤名稱，否則回退到帳號顯示名稱。每一天的出勤紀錄獨立保存；修改常用名稱不會自動重寫已登記班次，舊班次可由員工在該日按「儲存我的出勤名稱」更新。本機名稱快取僅作輔助，資料庫中的常用出勤名稱是跨裝置的主要來源。
- 站點只顯示會員**已登記出勤**，不代表館方額外審核過，也不代表當天能接受所有預約。應以館方公告為準。

## 驗收
1. 2026-11-15（週日）顯示 11/9–12/6；2026-11-16（週一）變為 11/16–12/13，總計仍是四週。
2. 沒有設定的 28 天都顯示未公告，員工不可登記出勤。
3. 管理員設定某日營業＋時段，自己以「婆婆」或自訂名稱按下「我會在這天出勤」，員工也可自行報班；旅人看到兩者的出勤顯示名稱。重新整理後資料仍存在，管理員可以自行取消。
4. 員工自訂不同於登入帳號的出勤名稱完成報班，再修改同一天名稱並儲存；確認前台名稱更新且原班次 ID、日期不變。嘗試以員工身分修改開店日、班次 ID 或他人出勤應受到資料庫拒絕；匿名者不能寫入。
5. 管理員設休館時，前台不公開員工出勤；重新開店後保留先前出勤紀錄。
6. 手機版依序顯示四週，並確認「/shifts/」和「/admin/shifts/」直接開啟／刷新不出現 404。
7. GitHub Actions `node scripts/qa-shift-roster.mjs` 自動檢查週一切換、台灣時區、四週／28 天、RLS、前後台和網站路由。
