# 狐隱 KOGAKURE｜網站背景音樂與入館流程

## 使用規則（2026-11-15）
- 前台每次新開啟網站，都以「希望播放」為預設，立即嘗試播放 BGMer 的〈みやびごころ〉；播放音量約 24%，單一播放器跨前台路由持續播放並循環。
- 手動點擊頁首 BGM 按鈕可以停止或重新播放；停止後在本次單頁網站瀏覽與切換前台頁面期間保持停止。**關閉設定不再寫入 localStorage**，重新載入網站會重新嘗試播放。
- Chrome、Safari 會依瀏覽器及使用者偏好阻止未經互動的有聲自動播放。網站程式不能強制繞過這個限制，因此無法保證「連點擊都不需要」就必定有聲。
- 若首次進入時播放要求遭拒，等狐隱的品牌開場畫面結束後，會顯示「進入狐隱・開啟音樂」入口。旅人點按按鈕的當下直接執行 `HTMLMediaElement.play()`，以符合瀏覽器的使用者互動政策；**不是**先更新 React 狀態再由延遲 effect 播放。
- 如果音源載入異常，入口提示重新嘗試；仍提供「暫不播放・直接入館」，避免第三方音源暫時失效時鎖死整個網站。
- 音樂已經開始播放時不顯示入館提示。原有品牌開場、場景循環、後台頁面及網站內容不受影響；管理員後台不自動播放 BGM。
- 前台頁尾保留音樂來源及授權資訊，音檔使用原有 BGMer 官方 URL。
- 音量、裝置靜音及使用者自行在瀏覽器禁止網站音效等條件不由網站控制，不應在宣傳中聲稱 100% 無條件有聲播放。

## 檢查
- GitHub Pages 部署：`npm run build`
- BGM 元件自動檢查：`node scripts/qa-site-bgm.mjs`
- 測試新訪客的 Chrome 或 Safari：未允許自動播放時出現入館播放按鈕；點擊後播音，切換頁面不中斷；頁首停止後切換頁面仍停止；重新載入則重新預設嘗試播放。
- 若 GitHub Actions 發布階段報出複數相同名稱的 `github-pages` artifact，請使用新的 workflow run（新的提交或 workflow_dispatch），不要在有多個同名 artifact 的 run 中反覆重試。
