## 發布原則

1. 先更新 GitHub 最新 `main`，在新分支修改，完成本機測試後以 PR 合併。
2. 原始碼／GitHub Pages、Supabase **migration**、Edge Function 是三種不同部署；PR 合併不會自動更新資料庫。
3. 任何正式資料庫變更須先確認環境、備份、相依版本、回復方式並取得授權。
4. 先測 RLS 邊界與敏感資料隔離，再交給店長驗收使用者介面。
5. 核對 `.github/workflows/verify.yml` 及 `deploy.yml`，並確認 Actions 成功後才對外公告功能。

詳見 `docs/SECURITY_REVIEW_20261117.md`、`docs/SUPABASE_SETUP.md` 及各模組手冊。
